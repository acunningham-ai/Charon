# /handoff — deliberate cross-session baton

Ends a working session so the next one (or a post-`/clear` context) resumes
without re-deriving. Distinct from `/eod-reflect` (daily synthesis) and
`/refresh-todo` (TODO regen): this is a *mid-project baton* whose headline
deliverable is a **paste-ready kickoff prompt**.

## Why half of it is generated, not written

A handoff composed by the model at the end of a session is a snapshot, and a
snapshot is stale the moment work continues. A note that still says "Phase 4 —
THE NEXT ACTION" hours after phase 4 shipped is the first thing the next session
reads, and it confidently misdirects. That is worse than no note.

So the note has two halves, and only one of them is written:

| Half | Source | Why |
|---|---|---|
| **Live state** — open commitments (with overdue), prior handoffs, drift | `scripts/handoff_state.py` | Knowable from the commitment register and the filesystem; must never disagree with reality |
| **The narrative** — what was done, why, what was tried and rejected, judgement calls | this session | Only the session that did the work knows it |

## Process

1. **Resolve the project** from `$ARGUMENTS`, else infer from the session and
   name it back for confirmation before writing.

2. **Generate the live block:**
   ```
   python scripts/handoff_state.py --project <Project>
   ```
   Paste its output into the note **verbatim**. Do not edit it — it carries a
   do-not-hand-edit marker, and correcting it by hand is exactly how a note
   starts disagreeing with the register. If it looks wrong, the register is
   wrong: fix that with `scripts/commitments.py` and regenerate.

3. **Author the narrative half** — Done this session / What was tried and
   rejected / Judgement calls a successor should not re-litigate / Highest-value
   artefacts (paths) / Next action. Be specific; this is the part that cannot be
   recovered from state.

4. **Supersede prior handoffs** for the same project: set `status: superseded`
   in the frontmatter of each earlier note. They stay on disk as dated history —
   never delete a handoff, it is a record of what was believed at the time.

5. **Write the note** → `08-Projects/<project>/handoffs/<YYYY-MM-DD>-<slug>.md`
   (create `handoffs/` if absent) with frontmatter: `type: handoff`, `project:`,
   `date:` (absolute — computer time is authority), `status: current`,
   `generated_by: claude-code /handoff`.

6. **Record any dated follow-up as a commitment**, not only as prose:
   ```
   python scripts/commitments.py --add "<what>" --date YYYY-MM-DD --kind review --ref <path>
   ```
   A next action that lives only in a handoff is invisible to TODO and to
   session start. This is the step that keeps the register the source of truth.

7. **Update the Pickups pointer** — propose a one-line update to `MEMORY.md` →
   `## 📌 Pickups (read first)` for this project (date + one-line status +
   ▶ next action). **Show the diff and ask before editing MEMORY.md** — never
   silent-write it.

8. **Verify:** `python scripts/handoff_state.py --check` — should report the
   superseded priors as handled and no contradictions.

9. **Emit the kickoff prompt** — fenced, self-contained, paste-ready after
   `/clear`: names the project, the handoff-note path, the 2-3 highest-value
   artefacts with *"read these first, don't re-derive"*, and the next action.

## Output artifacts

- `08-Projects/<project>/handoffs/<date>-<slug>.md` — the note.
- `status: superseded` set on prior handoffs for the project.
- Any dated follow-up added to the commitment register (`state/commitments.json`).
- A proposed `MEMORY.md` Pickups line (applied only on your yes).
- The inline kickoff prompt (not written to disk unless asked).

## Honest limit

`--check` compares handoffs against the register and against newer handoffs. It
cannot see work that finished but was never a register entry. **"drift: none" is
not "every handoff is accurate."** The gap closes as handoffs are regenerated and
dated work is tracked as commitments; it is not retroactive.

## When NOT to use

- **End-of-day reflection across all threads** → `/eod-reflect`.
- **Rebuild the TODO list from captures** → `/refresh-todo`.
- **Record a single durable fact/preference** → `/push-fact` / `/save-feedback`.

## Co-change couplings

- New handoff → supersede the priors **in the same run** (two "current" handoffs
  for one project is the drift this exists to prevent).
- Dated next action → the commitment register, same run.
- New handoff note → propose the `MEMORY.md` Pickups line same turn.
- Durable rule surfaced → `/save-feedback` / `/push-fact`; the handoff is
  transient state, not the system of record.
